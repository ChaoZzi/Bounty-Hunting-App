# 悬赏类 App 技术选型方案 v0.2

> 立项阶段决策记录
> 参考产品：赏帮赚（截图 6 张）
> 前提条件（v0.2 更新）：**个人全职开发 · 仅 Android · APK 直下 · 双边平台 · 悬赏主需实名 · 无 UI 设计稿 · 追求高端质感**

---

## 0. 本版变更（相对 v0.1）

| 项 | v0.1 | v0.2 | 原因 |
|---|---|---|---|
| 客户端 | uni-app | **Flutter** | 不做小程序/iOS，跨端优势归零；动效与音效是硬需求 |
| 端范围 | App + 小程序 + H5 | **仅 Android App + 官网下载页** | 明确不要小程序 |
| 架构 | 微服务可选 | **强制模块化单体** | 单人开发，运维成本必须趋零 |
| MQ | RocketMQ | **P0 不上，用事件表 + XXL-Job** | 少一个中间件就少一类故障 |
| 后台 | 独立 Vue 项目 | 保留，但用现成模板改 | 单人时间有限 |
| 支付 | 未定 | **支付宝为主，微信后续补** | 支付宝接入更快 |

## 1. 已锁定决策

| 决策项 | 结论 | 一句话理由 |
|---|---|---|
| 客户端框架 | **Flutter 3.x（Dart 3）** | 高动效 + 单代码库 + Dart 类 Java |
| 后端语言 | **Java 17 + Spring Boot 3.2** | 涉钱业务生态最成熟，你也有基础 |
| 后端形态 | **模块化单体**（单 jar） | 单人运维，一个进程最省心 |
| 数据库 | **MySQL 8.0** 单库 | 日 10 万单前不需要任何拆分 |
| 缓存 | **Redis 7** | 库存预扣、Token、限流、防重 |
| 定时任务 | **XXL-Job**（可退化 @Scheduled） | 超时关单、自动结算、对账 |
| 鉴权 | **Sa-Token**（而非 Spring Security） | 配置量少一个数量级，够用 |
| 后台 | **Vue3 + TS + Element Plus**（套 vue-pure-admin） | 不用从零搭 |
| 云 | **阿里云 ECS 2C4G 单机 + Docker Compose** | 月成本 100 出头 |
| 分发 | **官网 APK 直下 + 版本检查接口** | 不上架，省掉商店审核周期 |
| 支付 | **支付宝 App 支付 + 转账到支付宝账户** | 出款最省事，转账天然校验实名 |
| 对象存储 | **阿里云 OSS** | 凭证图多，自建 MinIO 反而更贵 |

## 2. 产品形态

三方角色：

| 角色 | 能做什么 |
|---|---|
| 接单用户（C） | 逛大厅 → 报名 → 做任务 → 传截图凭证 → 等审核 → 收赏金 → 提现 |
| 悬赏主（B） | **实名认证后** → 充值 → 发任务 → 设名额单价 → 置顶/加价/加量 → 审单 → 看数据 |
| 平台运营（你自己） | 任务审核、提现审核、实名审核、风控、内容安全、财务对账 |

**关键约束：悬赏主必须完成实名认证才能发布任务。** 这条要在后端做成硬拦截（`realname_status = 2` 才允许调 `POST /publisher/task`），前端只是提示，不能只靠前端。

平台收入结构（做架构时都要预留）：

1. **任务服务费**（悬赏主充值时的抽成）
2. **增值服务**（置顶 / 定时置顶 / 自动刷新 / 刷新包 / 置顶包 / 加价 / 加量 / 快审）—— 利润大头，本质是「广告位竞价」
3. **会员年卡**（截图里 2100/10000 信誉分 + 年度会员）
4. 附带：**广告联盟导流**（更多赚钱页的第三方 CPA）—— 后期再接，别放 P0

## 3. 总体架构（单人版）

```
┌─────────────────────────────────────────────┐
│  Flutter Android App（唯一客户端）            │
└──────────────────┬──────────────────────────┘
                   │ HTTPS
            ┌──────▼───────┐
            │    Nginx     │  TLS / 限流 / 静态资源 / APK 下载页
            └──────┬───────┘
                   │
      ┌────────────▼─────────────┐
      │  bounty-app.jar（单体）   │
      │  api / service / dao     │
      │  / job / common / boot   │
      └───┬────────┬────────┬─────┘
          │        │        │
    ┌─────▼──┐ ┌───▼───┐ ┌──▼──────┐
    │ MySQL8 │ │Redis7 │ │  OSS    │
    └────────┘ └───────┘ └─────────┘
                   │
            ┌──────▼───────┐
            │  XXL-Job     │ 超时关单/结算/对账/榜单
            └──────────────┘
```

一台 2C4G 跑得动：mysql(1G) + redis(256M) + jar(1G) + nginx。用户量到 5 万 DAU 再考虑加机器。

**刻意不做的事**（单人项目必须砍）：
- ❌ 微服务、注册中心、网关
- ❌ K8s
- ❌ RocketMQ（P0 用事件表 + 定时任务替代；P2 再引入）
- ❌ Elasticsearch（P0 用 MySQL 索引 + 简单排序）
- ❌ 分库分表、多租户、国际化

## 5. 为什么弃 uni-app 改 Flutter

| 维度 | uni-app | Flutter |
|---|---|---|
| 多端 | ✅ App+小程序+H5 | ❌ 仅移动端 |
| **动效上限** | 中（webview/原生混合，复杂动画掉帧） | **高**（自绘引擎，稳定 60/120fps） |
| **音效与触觉** | 需插件，延迟不可控 | 原生级，可做到 <50ms |
| **高端定制 UI** | 中等，受组件库约束 | **极强**，任何视觉都能画 |
| 语言 | JS/TS | Dart（**语法接近 Java**） |
| 包体积 | ~15MB | ~25MB（加固后 ~30MB） |
| 学习成本 | 低（若会 Vue） | 中（若会 Java 则较低） |

**结论**：「不做小程序、不做 iOS、要高端动效」三条同时成立时，uni-app 的护城河全部消失，Flutter 全面胜出。

> 备选：若你更习惯 Android 原生，可换 **Kotlin + Jetpack Compose**（同为 JVM 生态、Gradle 构建，与 Java 后端同构，动画能力同样顶级）。但 Compose 的动画曲线调试比 Flutter 略繁琐。

## 6. 单人开发的三个架构取舍

### 6.1 不做实时消息，做「拉 + 推兜底」
核心通知只有三类：审核结果、赏金到账、任务即将超时。
- 站内信表格 + App 启动/切前台时拉取未读数
- 极光推送做即时提醒
- **关键节点（提现到账）用短信兜底**，因为推送到达率不可控

### 6.2 审核先用「人工 + 规则」，不做 AI
- P0：人工审核队列 + 关键词黑名单 + 图片鉴黄
- P1：OCR 提取截图文字 → 正则匹配任务要求关键词 → 命中自动通过
- 别一上来接大模型审核，成本和误判都不可控

### 6.3 余额只记账，不做资金池
- 用户余额是**平台记账**，不是真钱
- 提现 = 先冻结 → 调用支付宝转账 → 成功后才扣减
- 每日对账：`sum(available + frozen + pending)` vs 流水汇总 vs 支付宝账单

## 7. 分发与更新（不上架商店的代价）

**方案：官网落地页 + OSS 存 APK + 版本检查接口**

```
GET /api/common/version?platform=android&versionCode=12
→ { latest: 13, url: "https://cdn.xxx.com/app/bounty-1.3.0.apk",
    force: false, changelog: "..." }
```

必须注意的四件事：

1. **App 备案（工信部）仍然要做**。2023 年起，在中国境内提供服务的 App 无论是否上架商店都必须备案，否则可能被下架/阻断。备案需要：主体资质 + 域名 + 服务器 IP + 承诺书。
2. **推送能力受限**。华为/小米/OPPO/vivo 的厂商推送通道通常要求 App 在对应商店上架。不上架 → 只剩极光自建长连接，**App 被系统杀掉后收不到通知**。对策：引导加自启动白名单 + 关键节点短信兜底。
3. **安装转化率会掉**。用户需手动允许「未知来源安装」，安卓 14 起还有额外确认。对策：下载页图文引导 + 二维码 + 分渠道包。
4. **防劫持**：APK 下载必须 HTTPS，做签名校验 + 文件哈希展示。

> 建议路线：P0 官网直下（自己人 + 种子用户），P1 补齐资质后上架华为/小米/OPPO/vivo/应用宝（免费），两条腿走路。

## 10. 合规与资质（比代码更早准备）

### 10.1 先解决「主体」问题 ⚠️
**个人身份做不了这个项目。** 以下能力全部要求营业执照：
- 支付宝/微信支付商户号
- 短信签名报备
- 实名认证 API
- App 备案
- 支付宝转账出款

**最低成本方案：注册个体工商户**（几百元，1-2 周），拿到营业执照 + 对公账户，即可开通支付宝 App 支付。

### 10.2 业务红线
- **不做刷单炒信**：任务不得指向电商虚假交易、好评返现、刷播放量/粉丝。涉嫌违反《反不正当竞争法》第八条、《电子商务法》第十七条，情节严重可构成非法经营罪。
- **安全的任务类型**：App 拉新下载注册、问卷调研、游戏试玩、内容体验、线下探店打卡、品牌活动参与、小程序体验。
- 落地措施：任务类型白名单 + 标题/描述关键词黑名单（"刷单""好评""返现""粉丝""播放量"）+ 人工初审。

### 10.3 资金红线
- 平台代收代付形成资金池 = 无证从事支付结算（"二清"）
- 合规做法：悬赏主充值走支付宝 → 平台记账 → 用户提现走**支付宝转账到账户**，平台只赚服务费
- 平台自有资金（新人奖、邀请奖）单独设营销账户，不混同

### 10.4 资质清单
- [ ] 营业执照（经营范围含"信息技术服务""软件开发"）
- [ ] ICP 备案（域名）
- [ ] **App 备案**（工信部，2024 起强制）
- [ ] 软件著作权
- [ ] 等保 2.0 二级（涉及支付/实名，后续必须）
- [ ] 隐私政策 + 个人信息收集清单 + 第三方 SDK 清单
- [ ] 支付宝商户号 + 应用审核
- [ ] 短信签名报备

### 10.5 其他
- 未成年人：18 岁以上门槛 + 实名（截图里已有该提示）
- 广告法：禁用"赢万元大奖""收益上不封顶"，改"有机会获得"
- 税务：用户收入达起征点需代扣代缴个税

## 11. 风险清单（按严重度排序）

| 风险 | 影响 | 对策 |
