## 0. 通用约定

### 0.1 响应结构

```json
{ "code": 0, "msg": "ok", "data": {}, "traceId": "a1b2c3" }
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / token 失效 |
| 403 | 无权限（如未实名发布任务） |
| 429 | 频率超限 |
| 1001 | 余额不足 |
| 1002 | 名额已满 |
| 1003 | 任务已下架 |
| 1004 | 重复报名 |
| 2001 | 实名未通过 |
| 5000 | 服务端异常 |

### 0.2 通用规则

- 鉴权头：`Authorization: Bearer <token>`（Sa-Token）
- 分页参数：`pageNum`（从 1 开始）、`pageSize`（默认 10，最大 50）
- 分页返回：`{ "list": [], "total": 0, "pageNum": 1, "pageSize": 10, "hasNext": true }`
- 金额单位：**元，字符串**（避免 JS 精度问题，如 `"3.20"`）
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 幂等：写接口一律支持可选 `Idempotency-Key` 请求头
- 图片上传：先调签名接口拿直传凭证，客户端直传 OSS，再把 URL 提交给业务接口

### 3.1 报名接口设计要点

```
POST /task/{id}/apply
→ 200 { "orderNo": "TO20261113001", "deadlineAt": "2026-11-14 12:00:00" }

错误：
1002 名额已满
1003 任务已下架/暂停
1004 重复报名（或已达每人限做次数）
2001 未实名（若任务要求）
```

服务端必须按此顺序执行：

1. 校验任务状态、时间窗口、`realname_status`
2. Redis Lua 原子扣减 `task:stock:{taskId}`，失败返回 1002
3. 写 `t_task_order`（唯一索引 `uk_task_user` 兜底并发重复）
4. 扣减失败要回滚 Redis 库存
5. 返回 deadline（`now + deadline_minutes`）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/order/my` | 是 | 我的任务列表，`status` 参数：`doing/pending/approved/rejected` |
| GET | `/order/{orderNo}` | 是 | 订单详情（含任务信息、倒计时、审核意见） |
| POST | `/order/{orderNo}/submit` | 是 | 提交凭证 `{images:[], content}` |
| POST | `/order/{orderNo}/cancel` | 是 | 放弃任务（释放名额，扣信誉分） |

| DELETE | `/order/{orderNo}` | 是 | 删除记录（仅超时/驳回态，逻辑删除） |

**状态流转：**

```
报名 → 1进行中 ──提交──→ 2待审核 ──通过──→ 3已通过 ──结算──→ 6已结算
                │              └──驳回──→ 4已驳回 ──重报──→ 1进行中
                └──超时──→ 5已超时
```

## 12. 定时任务（XXL-Job 调度，非 HTTP）

| JobHandler | 频率 | 职责 |
|---|---|---|
| `taskTimeoutJob` | 每 1 分钟 | 扫 `t_task_order` 中 `status=1 且 deadline_at < now` → 置 5 已超时，释放名额，扣信誉分 |
| `taskSettleJob` | 每 5 分钟 | 扫 `status=2` 且超 24h 未审 → 自动通过并结算（防悬赏主跑路） |
| `walletSettleJob` | 每 10 分钟 | 已通过订单 → 写流水、加余额、发消息 |
| `promotionExpireJob` | 每 5 分钟 | 置顶/刷新包到期处理，更新 `weight` |
| `inviteRewardJob` | 每小时 | 被邀请人完成首单 → 发邀请奖励 |
| `dailyReconcileJob` | 每日 02:00 | 对账 + 生成差异报告 |
| `dbBackupJob` | 每日 03:00 | mysqldump 上传 OSS |
| `riskScanJob` | 每小时 | 同设备/同IP多账号扫描，打风险标签 |

## 13. 开发顺序建议

```
1. auth + user + 上传签名      ← 第 1 周
2. task/hall + task/{id} + apply ← 第 2-3 周
3. order/my + submit + review    ← 第 3-4 周
4. wallet + withdraw             ← 第 5 周
5. admin 审核三件套              ← 第 6 周
6. publisher 发布与管理          ← 第 7 周
7. promotion + member            ← 第 8 周
8. pay 回调 + 对账               ← 第 11 周
```

> 先把 1-3 跑通就是一个可用闭环：**能登录、能看任务、能报名、能传图、能被审核、能看到结果**。这六件事对齐了，产品就立住了，其余都是加菜。
