# 本地私有化运行方案 v0.1

> 目标：App 装在自己手机上，后端跑在自己电脑上，不租服务器、不备案、不开支付、不对外运营。
> 前提：业务架构与线上版**完全一致**，只把外部依赖换成 Mock，未来可平滑上线。

---

## 1. 边界定义

| 项 | 是否做 | 说明 |
|---|---|---|
| 应用商店上架 | ❌ | 不需要 |
| 公网服务器 | ❌ | 后端跑本机 |
| 域名 / SSL / ICP 备案 | ❌ | 用局域网 IP 直连 |
| App 备案 | ❌ | 不对外分发，无需备案 |
| 支付宝 / 微信支付 | ❌ | Mock 支付 |
| 短信服务 | ❌ | 固定验证码 `123456` |
| 实名认证 API | ❌ | 后台手动点通过 |
| OSS | ❌ | 本地磁盘 |
| 推送 | ❌ | 改为启动/前台轮询 |
| 个体工商户 | ❌ | 不需要 |
| 多用户支持 | ✅ **保留** | 产品核心，不能因本地就退化成单用户 |
| 资金流水 / 对账 | ✅ **保留** | 这是业务核心，Mock 的是支付通道而非账本 |

**一句话：Mock 的是「通道」，不是「业务」。**

## 2. 架构

```
┌──────────────────────┐
│  你的 Android 手机     │
│  bounty.apk          │
└──────────┬───────────┘
           │ WiFi（同一局域网）
           │ http://192.168.1.x:8080
┌──────────▼───────────────────────────────┐
│  你的 Windows 电脑                         │
│  ┌────────────────────────────────────┐  │
│  │ Docker Desktop                      │  │
│  │  ┌──────────┐ ┌───────┐ ┌────────┐ │  │
│  │  │ mysql:8  │ │redis:7│ │ app.jar│ │  │
│  │  └──────────┘ └───────┘ └────────┘ │  │
│  └────────────────────────────────────┘  │
│  ./data/upload/  ← 凭证图片存这里          │
└──────────────────────────────────────────┘
```

- 后端监听 `0.0.0.0:8080`
- 手机与电脑必须在**同一个 WiFi**（手机不能走 5G 流量）
- 没有公网，外网访问不了，天然安全

## 4. Docker Compose

放在项目根目录 `docker-compose.yml`：

```yaml
version: "3.8"

services:
  mysql:
    image: mysql:8.0
    container_name: bounty-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: root123456
      MYSQL_DATABASE: bounty
      TZ: Asia/Shanghai
    ports:
      - "3307:3306"          # 避开本机可能已装的 3306
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./server/db/schema.sql:/docker-entrypoint-initdb.d/01-schema.sql:ro
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci

  redis:
    image: redis:7-alpine
    container_name: bounty-redis
    restart: unless-stopped
    ports:
      - "6380:6379"          # 避开本机可能已装的 6379
    volumes:
      - ./data/redis:/data
    command: redis-server --appendonly yes

  app:
    build: ./server
    container_name: bounty-app
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: local
      TZ: Asia/Shanghai
    volumes:
      - ./data/upload:/app/upload
      - ./logs:/app/logs
    depends_on:
      - mysql
      - redis
```

`server/Dockerfile`：

```dockerfile
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY target/bounty-boot.jar app.jar
ENV TZ=Asia/Shanghai
EXPOSE 8080
ENTRYPOINT ["java","-jar","/app/app.jar","--spring.profiles.active=local"]
```

`application-local.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://mysql:3306/bounty?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: root
    password: root123456
  data:
    redis:
      host: redis
      port: 6379
      database: 0
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 50MB
  web:
    resources:
      static-locations: file:/app/upload/

app:
  storage:
    type: local
    local-path: /app/upload
    public-prefix: http://192.168.1.23:8080/files/   # ← 改成你电脑的局域网 IP
  mock:
    sms-code: "123456"
    auto-pass-realname: true
    auto-pass-pay: true
```

> ⚠️ `public-prefix` 里的 IP 必须是**手机能访问到的那个 IP**，不是 `localhost`。

## 5. 手机连接配置

### 5.1 查电脑局域网 IP

```powershell
ipconfig
# 找 "无线局域网适配器 WLAN" 下的 IPv4 地址，如 192.168.1.23
```

### 5.2 固定 IP（重要）

DHCP 会变，导致 App 突然连不上。两种解法：

- **路由器里做 DHCP 静态绑定**（推荐，一劳永逸）
- 电脑设静态 IP
- 或在 App 设置页提供「服务器地址」输入框，随时改

### 5.3 Windows 防火墙放行

```powershell
New-NetFirewallRule -DisplayName "BountyApp-8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

### 5.4 Android 明文 HTTP 放行

Android 9+ 默认禁止 HTTP。在 `android/app/src/main/AndroidManifest.xml`：

```xml
<application
    android:usesCleartextTraffic="true"
    ... >
```

更严谨的做法是 `network_security_config.xml` 只放行局域网：

```xml
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">192.168.1.23</domain>
        <domain includeSubdomains="true">10.0.2.2</domain>
    </domain-config>
</network-security-config>
```

### 5.5 Flutter 里的 BaseUrl

```dart
class Env {
  // 真机：改成电脑局域网 IP
  // 模拟器：用 10.0.2.2（指向宿主机 localhost）
  static const String apiBase = String.fromEnvironment(
    'API_BASE',
    defaultValue: 'http://192.168.1.23:8080',
  );
}
```

构建时覆盖：

```bash
flutter build apk --release --dart-define=API_BASE=http://192.168.1.23:8080
```

## 6. 外部依赖 Mock 策略

| 能力 | 线上实现 | 本地实现 | 切换方式 |
|---|---|---|---|
| 短信验证码 | 阿里云短信 | 固定 `123456`，控制台打印 | `@Profile("local")` |
| 支付 | 支付宝 App 支付 | 假支付：直接置成功 + 写流水 | `@Profile("local")` |
| 实名认证 | 三要素 API | 提交即通过（或后台手动审） | `@Profile("local")` |
| 文件存储 | 阿里云 OSS | 本地磁盘 + 静态资源映射 | 配置 `app.storage.type` |
| 推送 | 极光 | 去掉；App 启动/前台拉未读数 | 前端轮询 |
| 短信通知 | 阿里云 | 写日志 | — |
| 内容安全 | 阿里云 | 关闭；后台人工看图 | — |
| 设备风控 | 数美 | 只记 `device_id`，不拦截 | — |

### 6.1 接口抽象（关键设计）

```java
public interface SmsService {
    void sendCode(String phone, String scene);
    boolean verify(String phone, String scene, String code);
}

@Profile("local")
@Service
public class MockSmsService implements SmsService {
    // 固定 123456，Redis 里也写 123456，方便前端调试
}

@Profile("!local")
@Service
public class AliyunSmsService implements SmsService { ... }
```

支付同理，但要注意：**Mock 支付只能改「通道调用」这一层，账本逻辑必须是真的**——
`t_pay_order` 状态机、`t_wallet_flow` 幂等、余额变动，全部按真实逻辑跑。否则以后接真支付必然出账。

### 6.2 Mock 支付的正确姿势

```
客户端点「支付」
  → POST /api/v1/pay/create   （照常建单，status=0 待支付）
  → local 环境直接返回 { mock: true, orderNo }
  → 客户端调 POST /api/v1/pay/mock-success { orderNo }
  → 服务端走与真实回调完全相同的处理逻辑（加锁、幂等、写流水）
  → 返回成功
```

真实回调 `AlipayNotifyController` 和 `MockPayController` 调用**同一个** `PayResultHandler`。这样以后换成真支付，只需关掉 mock 接口。

## 7. 图片存储（本地磁盘）

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Value("${app.storage.local-path}")
    private String localPath;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/files/**")
                .addResourceLocations("file:" + localPath + "/");
    }
}
```

- 路径：`./data/upload/2026/11/13/uuid.jpg`
- 上传接口先压缩到宽度 ≤ 1080、质量 80，再落盘（Flutter 端用 `flutter_image_compress` 先压一遍更省流量）
- 访问：`http://192.168.1.23:8080/files/2026/11/13/xxx.jpg`
- **不要用中文目录**，避免 Windows 编码问题

## 8. 打包与安装

### 8.1 首次生成签名

```bash
keytool -genkey -v -keystore bounty-key.jks -keyalg RSA -keysize 2048 \
        -validity 10000 -alias bounty
```

`android/key.properties`（**不要提交到 git**）：

```properties
storePassword=你的密码
keyPassword=你的密码
keyAlias=bounty
storeFile=../bounty-key.jks
```

> ⚠️ keystore 一定要备份。丢了就无法覆盖安装升级，只能卸载重装（数据全丢）。

### 8.2 构建

```bash
flutter build apk --release --split-per-abi \
  --dart-define=API_BASE=http://192.168.1.23:8080
```

产物：`build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`（现在手机基本都是 arm64）

### 8.3 传到手机（三种方式，任选）

```bash
# 方式 1：数据线 + adb
adb install -r app-arm64-v8a-release.apk

# 方式 2：电脑起个临时文件服务器，手机浏览器下载
python -m http.server 8000

# 方式 3：微信「文件传输助手」发给自己
```

### 8.4 安装

- 手机需开启「允许安装未知来源应用」
- 小米/华为还需关闭「纯净模式」/「应用安全检测」

## 10. 常见坑（都是会真实遇到的）

| 现象 | 原因 | 解决 |
|---|---|---|
| 手机连不上 | 手机走了 5G 流量 | 确认连的是同一 WiFi |
| 手机连不上 | Windows 防火墙拦截 | 放行 8080 入站 |
| 手机连不上 | IP 变了 | 路由器静态绑定 / App 内可改地址 |
| 请求报 `CLEARTEXT not permitted` | Android 9+ 禁 HTTP | `usesCleartextTraffic=true` |
| 图片 404 | `public-prefix` 写成了 `localhost` | 改成局域网 IP |
| 图片 404 | 容器内路径没挂载 | 检查 volumes |
| 上传失败 | 中文路径 | 用英文目录 |
| 端口冲突 | 本机已装 MySQL/Redis | 改用 3307 / 6380 |
| 电脑睡眠后失联 | 电源计划 | 改为「从不睡眠」 |
| 覆盖安装失败 | 签名不一致 | 保留同一个 keystore |
| 首次启动慢 | 拉镜像 | 一次性，之后很快 |
| 安卓 14 装不上 | 需额外确认 | 设置里允许「安装未知应用」 |

## 11. 想给朋友用怎么办

三种升级路径，成本递增：

### 路径 A：同一 WiFi（0 成本）
朋友连你家 WiFi 即可。缺点：只能在家用。适合内测。

### 路径 B：便宜云服务器 + 非标端口（约 100-200 元/年）
- 买 1C2G 轻量服务器
- 用 `http://公网IP:8080` 访问，**不需要备案**（80/443 才需要，8080 不用）
- 把 `docker-compose.yml` 原样搬上去
- 缺点：HTTP 明文，不适合放真实支付；适合小范围试用

### 路径 C：正式上线
按 `docs/技术选型方案.md` §10 补齐资质，然后把 §6 的 Mock 逐个换成真实实现。

**业务代码改动量：0。** 改的是 `@Profile` 实现类 + 配置 + 部署方式。

## 12. 排期调整

去掉合规与支付对接后，P0 从 12 周压缩到 **6-7 周**：

| 周 | 交付 |
|---|---|
| W1 | Docker 环境、Flutter 骨架、登录（Mock 短信） |
| W2 | 悬赏大厅、任务详情、设计 Token 落地 |
| W3 | 报名（Redis 库存）、我的任务四态 |
| W4 | 提交凭证、本地图片存储、审核流（Mock） |
| W5 | 钱包、流水、提现（Mock 打款） |
| W6 | 后台：任务/提现/实名审核 + 用户管理 |
| W7 | 悬赏主发布端、动效音效打磨、打包安装 |

**W3 结束时应该能在手机上完整走一遍：登录 → 看任务 → 报名 → 传图 → 后台审核 → 钱包到账。**
这一条链路跑通，剩下的都是加菜。

## 13. 仍然建议保留的东西

即使不上线，这四个别省：

1. **多用户体系**（手机号注册、JWT）—— 否则以后没法加真实用户
2. **资金流水表**（`t_wallet_flow` 幂等）—— 这是账本，Mock 支付也要写
3. **订单状态机**（7 个状态 + 流转日志）—— 业务复杂度就在这里
4. **实名门槛校验**（悬赏主必须实名）—— 你明确要的规则，Mock 也要走一遍流程

省掉这四个，做出来的东西只能叫「界面演示」，不叫「产品原型」。
